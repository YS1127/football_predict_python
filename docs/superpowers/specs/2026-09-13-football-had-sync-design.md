# 竞彩足球胜平负数据同步设计

## 目标

单次执行程序，从中国竞彩网同步竞彩足球胜平负（HAD）赛程、完整赔率变化和完场赛果到 MySQL。重复执行不得产生重复数据，业务逻辑可在以后被 HTTP 接口复用。

## 结构

程序分为官网客户端、响应解析、数据库模型/仓储、同步服务和命令入口。命令入口只负责启动同步与输出汇总；同步服务组织抓取和入库，不依赖 CLI，便于以后从 HTTP 接口调用。

## 数据表

### `matches`

每场比赛一行，以官网 `official_match_id` 唯一标识。保存竞彩编号、业务日期、联赛、主客队、开赛时间、比赛与销售状态、主客队全场进球、总进球、胜平负结果、开奖固定奖金，以及首次发现、最后发现和赛果更新时间。

全场比分按常规时间加伤停补时计算，不包含加时赛和点球大战。`had_result` 使用 `H`、`D`、`A`；未开奖字段为空。`total_goals` 必须等于主客队进球数之和。

### `odds_snapshots`

每次官网赔率发布时间对应一行，关联 `matches`。保存主胜、平、客胜三个 `DECIMAL` 赔率、官网发布时间、实际抓取时间和数据来源。

以 `(match_id, official_updated_at)` 建立唯一约束和查询索引。重复数据忽略；同一官网发布时间出现不同赔率时记录冲突并保留原记录。

所有官网时间按中国时区解释，以 MySQL `DATETIME` 保存。

## 同步流程

1. 获取当前 HAD 赛程并更新比赛表。
2. 获取比赛详情：新比赛补齐官网已有的全部赔率历史；已有比赛增量追加赔率。
3. 对数据库中尚未完场或未开奖的比赛继续查询详情，即使它已从当前列表消失。
4. 完场后回填主客队比分、总进球、HAD 结果及官网开奖奖金。
5. 每场比赛使用独立事务；单场失败不阻塞其他比赛。
6. 输出新增/更新比赛数、新增赔率数、回填赛果数和失败列表；存在失败时返回非零退出码。

## 异常处理

网络错误、超时、HTTP 429 和 5xx 使用有限次数退避重试。其他 4xx、非 JSON、官网失败响应、字段缺失和数据校验失败记录明确错误，不写入不可信数据。日志不得包含数据库密码或完整敏感响应。

## 测试

使用本地固定 JSON 样本测试解析，不让单元测试依赖官网。覆盖赛程解析、赔率历史、幂等重复同步、赛果回填、赔率冲突及单场失败隔离；数据库集成测试只使用独立测试库配置。

## 第一版边界

仅处理胜平负（HAD），不采集让球胜平负、比分投注、总进球投注或半全场赔率。第一版是单次执行命令，不包含常驻调度、消息队列或 HTTP 服务。
